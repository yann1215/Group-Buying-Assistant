# 微信 key 缓存保护

Windows 下 `decrypt_cache.json` 的 key 使用当前用户范围的 DPAPI 加密。
文件以 `format_version: 2`、`protection: dpapi` 标记，密文存放在
`key_encrypted` 中；其他账户信息、路径等元数据仍是明文。
程序运行时仅在内存中恢复 key，正常读取不会重新写入缓存。

读取旧版含合法 64 位十六进制 `key` 的缓存时，程序自动迁移：
写入同目录的加密临时文件，刷新到磁盘，重新读取解密并比较全部内容，
确认一致后原子替换原文件。不创建明文备份。
格式异常、解密失败、写入失败时保留原文件并报错，不退回明文保存。
非 Windows 平台不支持新建含 key 的缓存。

换账户、换电脑或重装系统后，旧缓存可能无法解密。应保留需要排查的文件，
然后通过程序的缓存清除功能（或手动移走该缓存文件）重新输入微信 key。
DPAPI 不隔离同一 Windows 用户下运行的其他程序。

本功能仅保护微信 key。它不加密 `app.db`、解密后的微信数据库、
聊天记录导出、订单缓存或归档，也不改变 `output` 的明文导出行为。
文件替换不保证擦除磁盘残留、历史备份或同步服务中的旧明文版本。

验证命令：`.venv\Scripts\python.exe -m scripts.verify_key_cache`。
测试在临时目录使用虚构 key，包含真实 DPAPI 往返、旧版迁移、
无效格式、解密失败以及原子替换失败的检查。
